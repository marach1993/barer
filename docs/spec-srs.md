# Բառեր — спецификация: интервальное повторение, сессии, алфавит

Версия 1 (спринт 1). Всё считается на клиенте: без сервера, без ML.

## 0. Базовые понятия

- **Логический день**: `dayNum = floor((Date.now() - tzOffsetMs - 4*3600e3) / 86400e3)`. День начинается в 04:00 по местному времени, так что ночные ответы идут в «вчера».
- **Сессия**: `sessionId = dayNum*2 + (localHour >= 14 ? 1 : 0)`: утренняя (0) и вечерняя (1). Шаг «в следующей сессии» = `sessionId + 1`. Так одно правило работает и для «утро→вечер», и для «вечер→утро».
- **Элемент повторения**: одна сторона карточки (`a` = Հայ→Рус, `b` = Рус→Հայ) или один навык буквы. У каждого своё состояние.

```js
// S.q[id] = { a: Side, b: Side }        // слова
// S.q["abc:<i>:<R|W|C>"] = Side          // алфавит (см. §4)
Side = {
  st: 0,     // 0 new, 1 learn, 2 review, 3 relearn, 4 suspended
  stp: 0,    // индекс шага обучения
  iv: 0,     // интервал, дни (float)
  ez: 2.5,   // ease
  due: 0,    // review: dayNum; learn/relearn: sessionId
  lp: 0,     // ошибок после выпуска (lapses)
  rp: 0,     // всего ответов
  lt: 0      // время последнего ответа, ms
}
```
Промежутки внутри сессии («через 3 карточки») **не сохраняются**. Если приложение закрыли посреди сессии, такие карточки при следующем открытии считаются просроченными.

## 1. Алгоритм (упрощённый SM-2 с оценкой по времени)

### 1.1 Оценка ответа
Пользователь ничего не оценивает вручную. Оценка `g` выводится так:

| Событие | g |
|---|---|
| Неверно / «Не знаю» | `AGAIN` |
| Верно, `ratio > 1.8` | `HARD` |
| Верно, `0.8 < ratio ≤ 1.8` | `GOOD` |
| Верно, `ratio ≤ 0.8` | `EASY` |
| Верно, но вкладка уходила в фон (`visibilitychange`) или `ms > 45000` | `GOOD` (время не учитываем) |

**Нормировка по длине.** Время от показа карточки до Enter включает набор, поэтому:
```js
const T0 = 1500;                                   // чтение и узнавание, ms
let mpc = S.cal || { a: 250, b: 450 };             // ms на символ; b медленнее (армянская раскладка)
function ratio(side, ms, answer) {                 // answer = самый короткий допустимый вариант
  const len = Math.max(2, norm(answer).length);
  return ms / (T0 + mpc[side] * len);
}
function calibrate(side, ms, answer, r) {          // только верные ответы, 0.5 ≤ r ≤ 3
  const len = Math.max(2, norm(answer).length);
  const x = (ms - T0) / len;
  mpc[side] = clamp(0.95 * mpc[side] + 0.05 * x, 120, 1200);
}
```
Калибровка подстраивается под темп пользователя: `EASY` означает «быстрее своего обычного», а не «быстрее абстрактной нормы». В фазах learn/relearn время **игнорируется**: любой верный ответ считается `GOOD`.

### 1.2 Шаги обучения

| Фаза | Шаги | Выпуск |
|---|---|---|
| Новое слово, сторона a | знакомство → +3 карточки → +8 → +20 (или конец сессии) → след. сессия | `iv = 1` (`EASY` на последнем шаге даёт `iv = 2`) |
| Новое слово, сторона b | +4 карточки → след. сессия | `iv = 1` |
| Relearn (после ошибки в review) | +4 карточки → след. сессия | `iv = max(1, round(iv_old * 0.25))` |
| Ошибка на любом шаге learn | вернуться на шаг «+3/+4» | — |

**Знакомство** (шаг 0, ответом не считается): экран со словом, переводом и примером, если он есть. Пользователь один раз перепечатывает армянское слово. Это даёт моторную память и сразу калибрует набор.

### 1.3 Пересчёт интервала (st = review)
```js
const P = { EZ0: 2.5, EZ_MIN: 1.3, EZ_MAX: 2.8, MAX_IV: 180, HARD_MUL: 1.2, EASY_BONUS: 1.3 };

function review(s, g, today) {
  const late = Math.max(0, today - s.due);          // на сколько дней опоздали
  let iv;
  if (g === AGAIN) {
    s.lp++; s.ez = Math.max(P.EZ_MIN, s.ez - 0.20);
    s.st = 3; s.stp = 0; s.ivOld = s.iv; return;    // → relearn
  }
  if (g === HARD) { iv = (s.iv + late * 0.25) * P.HARD_MUL;            s.ez = Math.max(P.EZ_MIN, s.ez - 0.15); }
  if (g === GOOD) { iv = (s.iv + late * 0.5)  * s.ez; }
  if (g === EASY) { iv = (s.iv + late)        * s.ez * P.EASY_BONUS;   s.ez = Math.min(P.EZ_MAX, s.ez + 0.10); }
  iv = Math.max(iv, s.iv + 1);                      // интервал всегда растёт
  iv = Math.min(iv, P.MAX_IV);
  s.iv = iv;
  s.due = today + balancedDay(iv, today);           // разброс + выравнивание нагрузки
}

function balancedDay(iv, today) {                   // разброс ±5% (минимум ±1 день при iv ≥ 3)
  if (iv < 3) return Math.round(iv);
  const d = Math.max(1, Math.round(iv * 0.05));
  let best = Math.round(iv), bestLoad = Infinity;
  for (let k = Math.round(iv) - d; k <= Math.round(iv) + d; k++) {
    const l = loadOn(today + k);                    // сколько review уже назначено на этот день
    if (l < bestLoad) { bestLoad = l; best = k; }
  }
  return best;
}
```
**Связь сторон.** Сторона `b` становится доступной (st 0→1) только после выпуска стороны `a` в review: сначала узнавание, потом воспроизведение. Если в сессии уже был review одной стороны, review другой стороны той же карточки откладывается на следующую сессию.

**Трудные слова (leech).** При `lp ≥ 5` карточка получает метку «трудное», а под ответом начинает показываться подсказка/пример. При `lp ≥ 8` приложение предлагает заморозить карточку (st 4).

## 2. Дневная сессия

| Параметр | Владелец | Новичок |
|---|---|---|
| Бюджет ответов на сессию `B` | 100 | 40 |
| Новых слов в день `NEW_DAY` | 20 | 8 |
| Новых за сессию `NEW_SES` | 10 | 4 |
| Рабочий набор (новых в learn одновременно) `WS` | 4 | 3 |
| Цена одного нового слова в ответах `C_NEW` | ≈5 | ≈5 |
| Порог «завала», после которого новые не даются | due > 150 | due > 60 |

### 2.1 Сборка очереди
```js
function buildSession() {
  const sid = sessionId(), today = dayNum();
  const learn  = items(s => (s.st===1||s.st===3) && s.due <= sid);          // шаги «след. сессия»
  const rev    = items(s => s.st===2 && s.due <= today)
                   .sort((x,y) => overdue(y)-overdue(x) || x.ez-y.ez);     // overdue = (today-due)/iv
  const revCap = Math.max(0, B - learn.length*1.5 - 20);                    // минимум 20 мест на новые
  const revQ   = rev.slice(0, revCap);                                       // остаток уходит на следующую сессию
  const free   = B - learn.length - revQ.length;
  const newLeft = NEW_DAY - newIntroducedToday();
  const nNew = (rev.length > BACKLOG) ? 0 : clamp(Math.floor(free / C_NEW), 0, Math.min(NEW_SES, newLeft));
  const newQ = pickNew(nNew);                       // сначала b-стороны выпущенных a, затем новые a по порядку базы/урока
  return interleave(learn, revQ, newQ);
}
```
- **Порядок в сессии**: сначала learn из прошлой сессии, потом review вперемешку с вводом новых. Новое слово вводится, только когда в learn меньше `WS` слов. Слово освобождает место в наборе, когда проходит шаг «+8».
- **Повторная вставка**: после ответа карточка в learn возвращается в очередь на позицию `cur + gap`. Если очередь короче, она встаёт в конец. Если сессия закончилась, слово ждёт следующей сессии (`due = sid + 1`).
- **Две сессии**: утром выбирается всё, что просрочено к сегодняшнему дню. Вечер получает learn-шаги «след. сессия» из утра, остаток review, если утренний бюджет его не вместил, и новые в пределах `NEW_DAY − утренние`. Если утро пропущено, вечер работает как обычная сессия, а лимиты остаются дневными.
- **Повторов больше 100**: в сессию идут первые `revCap` по приоритету «самые просроченные относительно интервала», при равенстве сначала меньший ease. Новые выключаются, пока due > `BACKLOG`. После конца сессии появляется кнопка «Ещё 50» (по желанию, не обязательна).

## 3. Миграция `{a,b,r,e,t}` → новое состояние

Выполняется один раз при `S.v < 2`. Старое `S.p` сохраняется в `S.p_v1` для отката.

| Верных `c` в эту сторону | Стартовое состояние | `iv` |
|---|---|---|
| 0 | new | — |
| 1–2 | learn, шаг «+8» | — |
| 3–5 | review | 1 |
| 6–10 | review | 3 |
| 11–20 | review | 7 |
| 21–35 | review | 14 |
| 36–49 | review | 21 |
| ≥ 50 | review | 30 |

```js
function migrateSide(c, r, e, aTot) {
  const errRate = e / Math.max(1, aTot + e);                 // aTot = a + b
  const ez = clamp(2.5 - 0.10*r - 1.0*errRate, 1.3, 2.7);
  let iv = ivFromCount(c);                                    // по таблице
  if (r >= 4 && iv > 1) iv = 1;                               // недавно много ошибок → повторить скоро
  return { st: c===0?0 : c<=2?1:2, stp: c<=2?2:0, iv, ez, due: 0, lp: 0, rp: c, lt: 0 };
}
// Распределение due без лавины (жадно, сначала самые слабые):
// sort по (iv, ez) по возрастанию; для каждой карточки due = первый день d из [0 .. min(iv,14)],
// где load[d] < CAP_MIG (день 0: 40, дни 1..14: 60); если мест нет, последний день диапазона.
```
Сторона `b` с `c ≥ 3` мигрирует сразу, даже если у `a` меньше 3 верных: правило «b после a» применяется только к новым словам.

## 4. Алфавит: мастерство вместо «50 раз»

**Упрощение.** Вместо 4 форм × 2 направлений остаются 3 навыка на букву:

| Ключ | Навык | Формат ответа | Старые ключи для миграции |
|---|---|---|---|
| `R` | печатная (заглавная или строчная, случайно) → звук | ввод кириллицей | `pu.a`, `pl.a` (берём min) |
| `W` | звук → печатная буква | выбор из 6 кнопок (2 из них из той же группы похожих) | `pu.b`, `pl.b` (min) |
| `C` | прописная → печатная | выбор из 6; модуль «Пропись», по умолчанию выключен | `cu.*`, `cl.*` (min) |

Если одна форма (заглавная или строчная) даёт ≥ 2 ошибок подряд, она показывается принудительно, пока не будет 2 верных подряд. Буквосочетание `ու` нужно добавить отдельным элементом для чтения, если его нет среди 39.

**Параметры SRS для букв**: шаги `+2 → +5 → след. сессия`, выпуск с `iv = 2`, ease фиксирован (2.5), `MAX_IV = 60`, время учитывается так же (`T0 = 1000`). Миграция: `c ≥ 10` → iv 14; 5–9 → iv 4; 1–4 → learn.

**Буква выучена**, когда у `R` и `W` `iv ≥ 7`. На практике это 3+ верных ответа в разные дни после обучения. Дальше буква появляется только по расписанию, примерно 1–3 буквы в день, и подмешивается в начало словесной сессии (до 5 ответов, без отдельного экрана).

**Входная проверка** (≈3 мин): 39 букв в случайном порядке, каждая по одному разу, навык `R`, форма случайная.
- Верно и `ratio ≤ 1.0` → `R` и `W` уходят в review с `iv = 14`.
- Верно, но медленно → `R` в review с `iv = 2`, `W` new.
- Неверно / «Не знаю» → new.
- Если первые 10 букв верные и быстрые, приложение предлагает «Похоже, алфавит вы знаете — пропустить?»: все буквы → iv 21 с разбросом по 14 дням. Если 3 «Не знаю» подряд, проверка заканчивается, оставшиеся буквы ставятся в new.

**Сессия новичка** (бюджет 60 ответов, ≈15 мин):
1. Learn и review по буквам.
2. Новая группа из 4 букв, если в learn меньше 4 букв. Порядок групп — по частотности букв в нашей базе слов (посчитать скриптом при сборке). Похожие буквы в одну группу не ставятся: фонетические тройки `բ/պ/փ`, `գ/կ/ք`, `դ/տ/թ`, `ձ/ծ/ց`, `ջ/ճ/չ`, `ր/ռ` и визуальные пары `գ/դ/ք`, `ն/ղ`, `ո/ռ`, `հ/ի`. Зато именно они подставляются как отвлекающие варианты в `W`.
3. **Чтение слов** — 5–10 заданий после каждой новой группы. Показывается слово из базы длиной 2–5 букв, составленное только из букв со `st ≥ 1`. Пользователь вводит транслитерацию кириллицей, для проверки строится регулярное выражение из вариантов по буквам (`ե`: `е|э|йе`, `փ`: `п|пх|п'`, `ու`: `у`, `ղ`: `г|гх|х`, `ը`: `ы|э|`…). После ответа показывается перевод. Верное прочтение засчитывается как `GOOD` для тех `R` из этого слова, у которых наступил срок, — это неявное повторение.
4. Новые слова для новичка открываются, когда выучено ≥ 20 букв. Для слов, где все буквы уже выучены, режим «Слова» доступен сразу.

## 5. Что показывать как прогресс

**Статус стороны карточки** (вместо «12/50»):

| Статус | Условие | Цвет |
|---|---|---|
| Новое | st 0 | серый |
| Учу | st 1/3 | оранжевый |
| Знакомо | review, iv < 7 | жёлтый |
| Знаю | 7 ≤ iv < 21 | светло-зелёный |
| Выучено | iv ≥ 21 | зелёный |

Карточка выучена, если обе стороны в статусе «Выучено». Трудное слово получает значок.

**Главный экран**:
- Сегодня: кольцо `ответов 87/100`, под ним `повторы 52 · новые 10/20 · точность 91%`.
- Слова: `Выучено 212 · Знаю 140 · Учу 18 · Новых 150` (полоса из 5 сегментов, по сторонам a/b отдельно).
- Прогноз: `Завтра ≈ 64 повтора + 20 новых`, мини-гистограмма на 7 дней (`loadOn(d)` + плановые новые).
- Удержание за 7 дней: доля верных в review. Если оно > 95%, предложить «+5 новых в день». Если < 80%, предложить «−5».
- Серия дней (streak) и «Алфавит: 31/39 букв выучено».

## 6. Краевые случаи

- **Синонимы**. В поле перевода варианты разделяются `/`, `;` или `,` (если запятая не внутри скобок). Подходит любой вариант. Часть в скобках необязательна: «(по)смотреть» принимает «смотреть» и «посмотреть». Нормализация: lower, trim, схлопывание пробелов, удаление `.,!?«»"-`, `ё→е`, для армянского `եւ≡և`, удаление ударений и знаков `՞ ՜ ՛`. Время нормируется по самому короткому варианту.
- **Кнопка «Засчитать»** после неверного ответа, если ответ был правильным синонимом. Она отменяет последнюю оценку (хранить снимок `Side` перед ответом), ставит `GOOD` и сохраняет вариант в `S.alt[id]`. Это не «почти верный», а исправление базы.
- **«Не знаю»** = `AGAIN`. Время не калибруется, правильный ответ показывается сразу.
- **Повторный ввод после ошибки**. Пользователь обязан перепечатать правильный ответ (Enter заблокирован до совпадения). На расписание и счётчики это не влияет. Карточка возвращается через `+4`.
- **Пропуск дня или недели**. Лавины нет: (1) бюджет сессии фиксирован, (2) приоритет у самых просроченных относительно интервала, (3) новые выключены при due > `BACKLOG`, (4) поправка `late` в §1.3 даёт карточкам, вспомненным после долгой паузы, заслуженно большой интервал. Learn-шаги, у которых `due < sid − 2`, начинаются заново с первого шага.
- **Режимы «Все» и «Ошибки»** — свободная практика. Верный ответ меняет только статистику, неверный ставит `due = min(due, today+1)` и `ez −= 0.1`. «Ошибки» = `lp ≥ 2` или `ez < 2.0` или ошибка за последние 3 дня.
- **Сброс**: по карточке («Учить заново» → st 0), по алфавиту, полный. Перед полным сбросом снимок кладётся в `S.backup` (1 копия) и предлагается «Отменить».
- **Хранилище**. У Telegram CloudStorage ограничения: значение ≤ 4096 символов, ≤ 1024 ключа. `Side` сериализуется компактно, массивом `[st,stp,iv*10|0,ez*100|0,due,lp,rp]`, а все карточки нарезаются чанками по ~3.5 КБ (`q0..qN`, ≈8–10 ключей на 520×2 сторон). `lt` хранится только локально. При конфликте облака и localStorage по каждой стороне побеждает запись с большим `rp`.
